GitHubへ上げる前の確認

GitHubへ公開する前に、現場ソース由来の解析結果が残っていないことを確認します。 解析成果物には、実ソースのパス、関数名、イベント名、データ名、呼び出し内容が含まれる場合があります。

重要: samples/sample.c、docs/index.html、ソースコード、README、ルールJSONは削除しません。 削除するのは解析成果物とPythonキャッシュです。
確認項目見るポイント
解析成果物output 配下にDB、Excel、DOT、CSVが残っていないか。
Pythonキャッシュ__pycache__ が残っていないか。
説明資料実ソースの具体的なパスや解析結果を貼り付けていないか。
ルールJSON公開してよい関数名、イベント名、データ名だけが残っているか。
ルールJSONの注意: 実ソースから生成した middleware_rules.local.json と middleware_rules.template.local.json はGitHubに上げないでください。 公開用の middleware_rules.json は空ルール、または公開可能なサンプルだけにしてください。

clean-projectの実行

GitHub公開前または他PC移行前に、以下を実行します。

python main.py --mode clean-project

このコマンドは削除対象一覧を表示したうえで、解析成果物とPythonキャッシュを削除します。

実ソース由来の痕跡削除対象

対象理由
output/*.dbSQLite DBには解析した実ソース由来の情報が含まれる。
output/*.xlsxExcelには関数名、呼び出し、イベント、データアクセス候補が含まれる。
output/*.dotDOTには関数呼び出し関係が含まれる。
output/*.csvCSV出力がある場合、解析結果を含む可能性がある。
output/*.json出力用JSONを作った場合、解析結果を含む可能性がある。
__pycache__/Python実行時のキャッシュ。公開には不要。
残すもの: samples/sample.c、docs/index.html、docs/github_migration.html、 main.py、analyzer/、README.md、middleware_rules.json、 middleware_rules.template.json、middleware_rules.example.json は削除対象ではありません。 ただし、これらは空またはサンプルのみの内容にしてください。

.gitignoreの意味

.gitignore は、Gitに登録しないファイルを指定するための設定です。 このプロジェクトでは、Pythonキャッシュ、仮想環境、解析成果物、ログ、一時ファイル、IDE設定、Windows固有ファイルを除外します。

分類除外例理由
Python__pycache__/, *.pyc自動生成されるため。
仮想環境.venv/, venv/PCごとに作り直すため。
解析成果物output/*.db, output/*.xlsx, output/*.dot, output/*.csv, output/*.json実ソース由来の情報を含む可能性があるため。
ローカルルールmiddleware_rules.local.json, middleware_rules.template.local.json実ソースから生成した関数名、イベント名、タスク名を含む可能性があるため。
ログ・一時ファイル*.log, *.tmp作業中に生成されるため。
IDE.vscode/, .idea/個人環境依存のため。
WindowsThumbs.db, Desktop.iniOSが生成するため。

GitHubへpushする手順

Gitが利用できる環境で、以下の順に実行します。

git init
git status
python main.py --mode clean-project
git status
git add .
git commit -m "Initial public version"
git branch -M main
git remote add origin https://github.com/USER/REPOSITORY.git
git push -u origin main
注意: git add . の前に git status を確認し、解析成果物が含まれていないことを確認してください。

別PCでcloneする手順

git clone https://github.com/USER/REPOSITORY.git
cd REPOSITORY

clone後、Python 3.13の仮想環境を作成して依存ライブラリをインストールします。

現場環境でミドルウェアルールを調整する場合は、middleware_rules.example.json または middleware_rules.template.json をコピーして middleware_rules.json を作成し、 ローカルで編集してください。 

copy middleware_rules.example.json middleware_rules.json
notepad middleware_rules.json

Python 3.13仮想環境作成手順

py -3.13 -m venv .venv
.venv\Scripts\activate
python --version
python -m pip install --upgrade pip

python --version でPython 3.13系が表示されることを確認してください。

オンライン環境での pip install

pip install -r requirements.txt

インターネット接続がある場合は、PyPIから必要ライブラリを取得します。

オフライン環境での wheelhouse インストール

事前に offline_packages/wheelhouse が用意されている場合は、以下を実行します。

pip install --no-index --find-links offline_packages/wheelhouse -r requirements.txt

wheelはPythonバージョンやOSに依存します。Python 3.13用のwheelを使う場合は、移行先PCでもPython 3.13を使用してください。

動作確認コマンド

python main.py --mode ast --src samples
python main.py --mode scan --src samples
python main.py --mode analyze --src samples
python main.py --mode export
python main.py --mode graph

サンプルで動作確認してから、必要に応じて実ソースを解析してください。

注意事項

  • GitHub公開前に python main.py --mode clean-project を実行してください。
  • output 配下の解析成果物はGit管理しないでください。
  • 実ソースの具体的なパスや解析結果をREADMEやHTMLに貼り付けないでください。
  • 実ソースから生成した middleware_rules.local.json はGitHubに上げないでください。
  • GitHub公開用の middleware_rules.json は空、または公開可能なサンプルだけにしてください。
  • ルール調整後のファイルはローカル管理とし、公開前に内容を見直してください。
  • オフライン移行では、移行先Pythonのバージョンとwheelhouseの対応を確認してください。
  • まず samples で動作確認してから実ソース解析へ進んでください。
